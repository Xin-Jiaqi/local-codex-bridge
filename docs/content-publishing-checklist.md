# 内容发布检查清单（知乎 / 小红书）

> 用途：`docs/zhihu-v1.md`（知乎长文）与 `docs/xhs-v1.md`（小红书图文）发布前的
> 统一检查清单。内容发布**始终由用户人工完成**：本仓库没有任何自动发布脚本，
> 也不要把内容发布与软件 release 绑定在同一天。

## 1. 编辑门槛（内部口径，不是外部评级）

- 知乎文字稿：独立 review **90/100，P0=0**。
- 小红书稿：独立 review **94/100，P0=0**。
- 这两个数字是仓库内部的编辑质量门槛（达到即可进入人工发布流程），
  **不是**任何外部平台的评级，不要在内容里引用或暗示"评分/评级"。

## 3. 截图隐私检查（发布前逐张过）

- 不出现：API key / token（含 `sk-`、`ghp_`、`Bearer <key>` 形态）、
  `.bridge_api_key` 文件内容、私有 ngrok 域名（对比 `.ngrok_domain`）、
  运行时日志内容（`.runtime/*.log` 含 thread 文本与命令，不能截）、
  个人绝对路径（`/Users/<name>/...`）、真实 PID。
- 可以出现：公开 GitHub repo URL（`https://github.com/Xin-Jiaqi/local-codex-bridge`）、
  本地 `127.0.0.1` health 输出、打码后的任意敏感字段。
- 检查方式：截图前先 `rg` 一遍目标输出里的敏感模式；截图后人工放大检查边缘。

## 4. 时点同步（v1.1.0 release 后必做）

- 内容稿目前以「v1.1.0 unreleased / 当前工作区」为叙事时点（这是编辑时点，
  不是永恒状态）。
- **GitHub v1.1.0 Release 发布后**，发布任何内容前，必须把内容稿中的
  unreleased / 当前工作区 时点文字做一次 **final sync**：
  - zhihu：把"本文整理时仍在发布前验证阶段"等叙事时点改为按 release notes
    的事实描述（v1.1.0 已发布、包含哪些修复），不声称未验证的 runtime 结果；
  - xhs：按 `docs/xhs-v1.md` 顶部「发布后同步点」注记执行（unreleased 提示
    改为 released、卡 9 换 Release 截图）。
- final sync 之后才进入配图与发布。

## 5. 发布流程（人工）

1. 用户审阅全文（文风、事实、截图）。
2. 用户补图 / 换图，按第 3 节做隐私检查。
3. 用户手动发布到知乎 / 小红书（**不自动发布**）。
4. 发布后可选：在下方表格记录文章 URL（不预填，未发布不写）。

| 平台 | 文章标题 | 发布状态 | URL（发布后填） |
|---|---|---|---|
| 知乎 | 把 ChatGPT 接到本地 Codex CLI：从复制命令到一句话直接操作本地项目 | ☐ | |
| 小红书 | 待定（xhs-v1.md 标题候选 1–3 选一） | ☐ | |

## 6. 不在本清单范围内

- 软件 release 的执行（见 `docs/release-process.md`）与内容发布相互独立；
  内容稿可以先于或后于软件 release 完成，但**内容发布前**必须完成第 4 节同步。
- 本清单不替代 README / SECURITY 的边界口径，涉及能力描述以仓库文档为准。
